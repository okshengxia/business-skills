# 5Why 方法参考

## 方法本质

5Why 不是"问五次为什么"，而是沿因果链逐层下探，直到找到那个"移除后问题不再发生"的系统性原因。

- 起源：丰田佐吉提出，大野耐一在丰田生产体系中系统化使用。
- 核心假设：问题的表层原因与根本原因之间，通常隔着 3-6 层可观测的因果环节。
- 适用：重复发生的业务问题、流程缺陷、质量事故、组织协作失效。
- 不适用：一次性偶发事件、需要定量归因而非机制归因的问题。

## 追问的五条纪律

1. **单点聚焦**：一轮只问一个为什么，等回答后再继续。
2. **链式衔接**：下一个为什么必须建立在上一个回答之上，不能另起话题。
3. **事实优先**：每个回答尽量落到可观察的事件、数据、记录上。
4. **对事不对人**：出现"某人的态度/能力/疏忽"时，转向"什么机制允许它发生"。
5. **可行动边界**：追到组织能改变的那一层就停，不追到"人性"或"行业规律"。

## 常见陷阱

| 陷阱 | 表现 | 纠正 |
|---|---|---|
| 归咎于人 | "因为员工不认真" | 问：为什么流程没有拦住这个失误？ |
| 伪根因 | "因为培训不足""意识不够" | 问：为什么现有机制没能发现并纠正？ |
| 逻辑跳跃 | 从"客户流失"直接跳到"产品不行" | 要求补上中间可观测的证据 |
| 多因混淆 | 一个回答里塞了三个原因 | 拆开，让用户选影响最大的一个 |
| 凑数 | 硬问满五个为什么 | 根因出现即停 |
| 预设结论 | 提问在诱导用户确认自己的判断 | 用中性问句，不嵌入答案 |
| 停在表象 | 把"系统报错"当根因 | 继续问：为什么这个报错没有被提前发现？ |

## 根因判断

一个原因可以视为根因，当它同时满足：

1. **不可再问**：继续问"为什么"只会得到不可行动的回答。
2. **移除有效**：假设它被消除，问题链条会断，不再复发。
3. **组织可控**：它属于流程、标准、机制、工具、资源或假设，而非个人品性或外部规律。

## 逆向验证（"所以"测试）

从疑似根因正向复述整条链：

> 因为［根因］，所以发生了［Why N-1］；因为［Why N-1］，所以发生了［Why N-2］……最终导致了［最初的问题］。

每一环都要能用事实或记录支撑。任何一环说不通，说明根因找早了或链条断了。

## 对策设计

- **根本对策**：改变产生根因的机制（流程、标准、权限、工具、激励）。
- **临时对策**：先止血，防止问题在修复期间扩大。
- **验证设计**：每条对策配一个领先指标（不是结果指标），并设定复盘时间。
- **反脆弱检查**：新对策会不会制造新的瓶颈或把风险转移到别的环节？

## 对话节奏

- 用户回答短、准：直接进入下一个为什么。
- 用户回答长、散：先复述提炼成一句，再追问。
- 用户情绪化：先承认问题带来的压力，再把话题拉回流程。
- 用户想跳过分析：说明"没有根因的对策大概率会复发"，再让其选择继续或先给临时对策。
