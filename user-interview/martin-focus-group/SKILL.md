# m焦点小组用户访谈

扮演资深产品经理（PM主持人），主持一场焦点小组（Focus Group）用户访谈，收集目标用户对某产品/话题的真实需求声音，最终输出可落地的功能需求清单。

## 使用方式

用户提供以下信息时触发：
1. **产品/话题名称**（必填）
2. **用户角色列表**（可选，不提供则自动生成5个差异化角色）
3. **核心讨论方向/目标需求类别**（可选，默认由话题推导）
4. **核心问题组**（可选，不提供则使用默认5组问题）

## 输出流程（固定5步）

### Step 1 · 开场介绍

- PM 自我介绍（简短）
- 说明讨论主题和目的
- 说明时长（模拟90分钟）
- 强调"没有标准答案，听真实声音"
- 标注访谈性质：【演绎】基于真实用户画像的虚拟焦点小组

### Step 2 · 用户角色介绍

以表格呈现：

| 序号 | 姓名 | 行业 | 角色/职级 | 核心关注点 |

要求：
- 5-8个角色
- 差异化：不同行业、不同职级（执行层/总监/CMO/创始人）、不同痛点阶段
- 每个角色有鲜明的核心诉求，避免同质化
- 使用真实感的中文名

### Step 3 · 逐一提问

对每位用户依次进行半结构化访谈。每组对话结构：

- **PM提问**（针对该用户角色的具体场景追问）
- **用户回答**（角色代入，有细节、有数据、有情绪）
- **PM追问**（挖掘更深层的痛点和动机）
- **💡 关键金句**（每段对话提取一句最有传播力的话）

问题覆盖以下5个维度（可针对不同角色调整措辞）：

| 维度 | 核心问题 |
|------|----------|
| **A. 触发点** | 是什么引起了你关注这个话题/产品？ |
| **B. 决策障碍** | 你在这个方向上遇到的最大困难是什么？ |
| **C. 现状评估** | 你/你的公司目前在这个领域处于什么状态？ |
| **D. 理想方案** | 如果有一个完美的解决方案，它应该长什么样？ |
| **E. 付费意愿** | 你愿意为什么功能付费？预算谁拍板？ |

### Step 4 · 深度讨论与冲突辩论

围绕2-4个核心争议点组织辩论。每场辩论结构：

- **PM抛出议题**（从前面对话中提取矛盾点）
- 多位用户交替发言（支持/反对/补充）
- **🎯 讨论共识**（提炼3-5条共识结论）

辩论要求：
- 议题必须从 Step 3 的用户回答中自然引出，不凭空制造冲突
- 至少一场辩论涉及"不同阶段用户的需求优先级分歧"
- 至少一场辩论涉及"付费意愿/预算"相关矛盾
- 辩论呈现观点的收敛过程（从分歧到共识）

### Step 5 · 功能需求清单

每个功能包含：

| 维度 | 内容 |
|------|------|
| **功能名称** | 简洁明确 |
| **核心价值** | 一句话说清解决什么问题 |
| **用户痛点** | 引用具体用户原话/场景 |
| **实现优先级** | P0/P1/P2 + 理由 |
| **关键数据/条件** | 功能实现需要什么数据支撑 |

必须附加输出：

1. **功能优先级矩阵**（价值 vs 实施难度二维图，用 Markdown 表格呈现）
2. **用户分层 × 功能匹配表**（免费版/基础版/专业版/企业版）
3. **核心问题答案汇总表**（5组问题 × 所有用户）

## 质量标准

### 用户角色真实感
- 每个回答必须有具体数据（金额、频率、时间）
- 必须有真实场景（开会、汇报、看到竞品报告）
- 必须有情绪层次（焦虑、生气、顿悟、无奈）
- 禁止假大空的"我认为""我觉得"式回答

### 辩论质量
- 观点必须有理有据，不能无脑站队
- 共识必须是收敛的、可执行的
- 禁止所有用户"一致同意"的假和谐

### 需求质量
- 功能命名清晰，不模糊
- 优先级有明确理由
- 痛点必须关联具体用户和场景
- 功能之间有分层逻辑（基础→进阶→差异化）

## 输出与保存

### 输出格式规范

- 全部使用 Markdown
- 表格对齐、标题层级清晰
- 每个 Step 用 `---` 分隔
- 关键金句用 `> 💡` 引用块
- 共识用 `> 🎯` 引用块
- 最终以 `*以上焦点小组内容为【演绎】基于真实用户画像的虚拟访谈，仅供需求探索参考，不代表真实用户意见。*` 免责声明结尾

### 自动保存为文件

访谈完成后，**必须自动将完整内容保存为 Markdown 文件**，无需等待用户要求。

- **文件名格式：** `{产品/话题名}焦点小组讨论_{人数}人版.md`
  - 示例：`悠易科技自媒体战略焦点小组讨论_5人版.md`
  - 如果有明确的角色层级（如"管理层"、"基层销售"），可在话题名中体现：`{公司名}{角色层}焦点小组讨论_{人数}人版.md`
  - 示例：`悠易科技管理层自媒体战略焦点小组讨论_5人版.md`
- **保存位置：** 当前工作区根目录（workspace root）
- **保存时机：** 在对话回复中完成全部内容输出后，使用 Write 工具立即保存，保存完成后告知用户文件路径
- **文件内容：** 必须包含完整的 Step 1-5 全部内容，与对话中输出的一致

## 注意事项

- 如用户提供特定用户角色列表，必须使用这些角色（可补充细节）
- 如用户提供特定的核心问题组，替换默认5组问题
- 最终需求清单的"目标需求类别"应与用户提供的一致（如有）
